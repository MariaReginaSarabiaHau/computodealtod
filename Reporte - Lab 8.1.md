# Reporte de Laboratorio 8.1: Migrating a Web Application to Docker Containers
En este laboratorio trabajé en la migración de una aplicación web a contenedores Docker dentro de AWS, retomando el rol de Sofía, la encargada de integrar la aplicación de proveedores de café a la infraestructura de la cafetería. El objetivo general fue dejar de depender de aplicaciones instaladas directamente sobre instancias EC2 y pasar a un esquema más portable y escalable basado en imágenes de Docker, tanto para la aplicación en Node.js como para la base de datos MySQL, y finalmente registrar estas imágenes en Amazon ECR para usarlas en futuras implementaciones.

- ### Tarea 1
> En la Tarea 1 preparé el entorno de desarrollo. Primero accedí al IDE de VS Code en la nube usando la URL y la contraseña del laboratorio. Desde ahí descargué y descomprimí el archivo code.zip con el código de la aplicación, ejecuté un script de configuración (setup.sh) para actualizar Python y la AWS CLI, y verifiqué que la CLI estuviera en la versión 2 y que el SDK de Python (boto3) estuviera instalado. Esta parte fue básicamente dejar listo el entorno de trabajo para poder construir imágenes, correr contenedores y usar los comandos de AWS sin problemas.

- ### Tarea 2
> En la Tarea 2 analicé la infraestructura existente de la aplicación. Entré a la consola de EC2, identifiqué las instancias en ejecución (el IDE, el servidor de aplicación y el servidor MySQL) y abrí en el navegador el sitio de proveedores de café usando la IP pública de AppServerNode. Probé la aplicación agregando y editando un proveedor para confirmar que la lógica funcionaba y que los cambios se guardaban en la base de datos. Después revisé el código en el IDE, dentro de resources/codebase_partner, donde pude ver que la app estaba hecha con Express en Node.js, corriendo originalmente sobre el sistema operativo de la instancia EC2 y conectándose a MySQL.

- ### Tarea 3

> En la Tarea 3 comencé la migración de la aplicación a un contenedor Docker. Para esto creé un directorio containers/node_app, moví allí el código de la aplicación y construí un Dockerfile que define la imagen base (node:11-alpine), el directorio de trabajo, la copia del código, la instalación de dependencias y la exposición del puerto 3000. Luego ejecuté docker build para crear la imagen node_app y verifiqué que estuviera disponible con docker images. Después corrí el contenedor con docker run -d -p 3000:3000 y probé con curl que la aplicación respondiera en localhost:3000. Finalmente, ajusté las reglas del grupo de seguridad del IDE para abrir el puerto 3000 desde mi IP y comprobé en el navegador que ahora la app se servía desde el contenedor. En esta parte también identifiqué el problema de conexión a la base de datos: la app usaba una IP codificada en config.js y no estaba recibiendo la variable de entorno APP_DB_HOST, así que la primera vez el contenedor no podía comunicarse con MySQL.

> Todavía dentro de la migración, corregí ese problema deteniendo el contenedor anterior y arrancando uno nuevo, esta vez pasando APP_DB_HOST como variable de entorno con la IP de MysqlServerNode. Primero confirmé dentro del contenedor, usando docker exec y env, que la variable sí estuviera presente; luego probé otra vez la aplicación vía navegador y verifiqué que ahora sí podía listar proveedores y leer los datos de la base de datos. Con esto completé la migración de la aplicación de Node.js a Docker, asegurando la comunicación correcta con MySQL mediante variables de entorno y no con direcciones IP fijas.

- ### Tarea 4 y 5

> En la Tarea 4 y 5 migré la base de datos MySQL a otro contenedor Docker y la probé junto con la app. Generé un mysqldump de la base de datos COFFEE desde la instancia MySQL original, guardándolo como my_sql.sql, y le hice un pequeño cambio a la dirección del proveedor para poder diferenciar luego si estaba leyendo de la nueva base. Después creé el directorio containers/mysql, moví el archivo .sql ahí y definí un Dockerfile basado en mysql:8.0.23, exponiendo el puerto 3306 y copiando el script. Construí la imagen mysql_server y ejecuté el contenedor mysql_1, importé el dump dentro del contenedor y creé el usuario nodeapp. Luego detuve el contenedor de la app, obtuve la IP interna del contenedor mysql_1 con docker inspect y volví a levantar node_app_1 pasándole APP_DB_HOST con esa IP interna. Al probar la aplicación en el navegador y ver la dirección modificada (por ejemplo, “Container Street”), confirmé que ahora la app de Node y MySQL se estaban comunicando entre sí como contenedores, no con la base de datos original de EC2.

- ### Conclusión 

Finalmente, en la Tarea 6 agregué la imagen de la aplicación a Amazon ECR. Primero obtuve el ID de mi cuenta de AWS y usé aws ecr get-login-password para autenticar el cliente de Docker contra ECR. Luego creé el repositorio node-app, etiqueté la imagen local node_app:latest con el nombre completo del repositorio de ECR (incluyendo el registryId) y ejecuté docker push para subir la imagen. Verifiqué la carga con aws ecr list-images, donde apareció la imagen con la etiqueta latest. Al terminar el laboratorio, dejé corriendo ambos contenedores (la app y MySQL) para asegurar el crédito completo. En resumen, en este laboratorio logré contenerizar la aplicación web y la base de datos, solucionar los detalles de conectividad mediante variables de entorno y registrar la imagen de la aplicación en Amazon ECR, dejándola lista para futuras implementaciones con servicios como Elastic Beanstalk.
